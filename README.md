# mc: a Minecraft-style voxel game for browser, Windows and Android

A from-scratch Minecraft-style sandbox written in plain JavaScript with **raw WebGL2** (no libraries, no build step).
It runs on **GitHub Pages**, as a **Windows `.exe`** (Electron, built by GitHub Actions) and as an **Android `.apk`** (Capacitor, built by GitHub Actions).

All textures, sounds and the font are **generated by code** (original pixel art in the vanilla style).
No Mojang assets are used or included, and none should ever be added.

### One-time setup the repo owner must do
1. GitHub repo → **Settings → Pages → Build and deployment → Source: GitHub Actions**. (Without this the Pages workflow cannot publish.)
2. Windows build: **Actions → "Build Windows"** → open the latest run → download the **MC-Windows** artifact → unzip → double-click the `.exe`.
   Windows SmartScreen will warn (the app is unsigned): **More info → Run anyway**.
3. Android build: **Actions → "Build Android"** → download the **MC-Android-APK** artifact → unzip → install `app-debug.apk` on the phone (allow "install unknown apps").

## 🧭 Architecture & file map

Planned layout (files marked ✔ exist):

```
index.html              page shell: <canvas id=gl>, <canvas id=ui>, error overlay
js/package.json         {"type":"module"} so Node can import the game logic for tests
js/util.js              RNG, hashing, math helpers
js/noise.js             seeded improved Perlin noise + octave helpers
js/blocks.js            block registry (ids, textures, hardness, light, models)
js/textures.js          procedural texture generation (pure JS, runs in browser AND Node)
js/items.js             items, tools, recipes, drops
js/worldgen.js          terrain, biomes, caves, ores, trees (deterministic from seed)
js/chunk.js             Chunk class
js/world.js             world, chunk pipeline, set/get block, raycast, collision
js/light.js             sky + block light BFS
js/mesher.js            section -> vertex/index arrays (pure, testable in Node)
js/renderer.js          WebGL2 renderer
js/player.js            player physics & state
js/input.js             keyboard / mouse / touch
js/ui.js                canvas GUI, font, menus, inventory
js/save.js              IndexedDB persistence
js/main.js              boot + game loop
sw.js, manifest.webmanifest, icons/
electron/               Windows desktop wrapper
.github/workflows/      pages.yml, windows.yml, android.yml
tools/                  Node-only dev tools: PNG encoder, atlas dump, software preview render, tests
```

### Key design decisions (read before editing)
- **No dependencies.** Everything is raw WebGL2 + Canvas2D. Nothing to install, works offline.
- **World = f(seed) + edit diff.** Only player edits are saved. Terrain is regenerated deterministically.
- **Chunk = 16 x 256 x 16**, stored as `Uint16Array` (`id = v & 255`, `data = v >> 8`), index `x | z<<4 | y<<8`.
- **Decorations are order-independent**: a chunk is finalised from 4 contributor chunks; each placement uses a priority rule (air < plant < leaves < log), so results never depend on load order.
- **Textures**: one `TEXTURE_2D_ARRAY` (16x16 layers) so mipmaps never bleed. Alpha of opaque layers can act as a tint mask (grass side overlay).
- **Fixed 20 TPS game tick** with render interpolation, to match vanilla movement feel.

### Dev environment gotchas
- The Claude sandbox has **no network for npm/pip**; test with plain Node 22 (no packages). CI has network.
- Game code in `js/` is ES modules; Node tests live in `tools/*.mjs` and import from `../js/…`.
- There is no browser in the sandbox: `tools/preview.mjs` is a software raycaster that renders the world to a PNG for visual checks, and `tools/smoke.mjs` boots the game against a stubbed DOM/WebGL to catch runtime errors.
